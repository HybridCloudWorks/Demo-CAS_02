# Azure Arc onboarding decision matrix (verified October 2026)

| Environment | Recommended method | Prerequisites | Required roles | Guest agents | Network dependencies | Support status | Live-demo reliability | Fallback |
|---|---|---|---|---|---|---|---|---|
| **Hyper-V (arc-hyperv-demo, optional path; not used in the CAS 2026 delivery)** | Direct Connected Machine agent, `azcmagent connect --use-device-code` | Ubuntu 24.04 x86-64; RG exists; providers registered (HybridCompute, GuestConfiguration, HybridConnectivity) | *Azure Connected Machine Onboarding* at RG scope (user signing in via device code) | azcmagent (himds, gc, extension manager); optional linux-cloud-tools-virtual for KVP IP reporting | Outbound 443 to login.microsoftonline.com, management.azure.com, *.his.arc.azure.com, *.guestconfiguration.azure.com, *.servicebus.windows.net, packages.microsoft.com | **GA** | **High** — immediate, visible success in console; 5-minute device-code window | Pre-onboarded checkpoint of the VM (connect before session, keep checkpoint taken *before* connect for rebuild) |
| **AWS (arc-aws-demo)** | Direct agent via SSM Session Manager, `--use-device-code --resource-name arc-aws-demo` | EC2 with SSM instance profile; SG egress 443; same Azure prerequisites | Onboarding role (Azure); `AmazonSSMManagedInstanceCore` on the instance role (AWS) | azcmagent; SSM Agent (preinstalled on Ubuntu AMIs — verification required) | As above plus SSM endpoints (ssm, ssmmessages, ec2messages) | **GA** (direct agent); multicloud connector for AWS **GA** but periodic (daily default, 15-min minimum) and skips machines already Arc-enabled | **High** (direct); **Low** for live connector onboarding because of the sync schedule | Multicloud connector *inventory* pre-staged as a read-only view; or pre-onboarded before session |
| **Google Cloud (arc-gcp-demo)** | Direct agent via IAP TCP forwarding + OS Login, `--use-device-code --resource-name arc-gcp-demo` | GCE VM; firewall allows 35.235.240.0/20 → 22; APIs compute, iap, oslogin enabled; same Azure prerequisites | Onboarding role (Azure); `roles/compute.osAdminLogin` + `roles/iap.tunnelResourceAccessor` for the instructor (GCP) | azcmagent; OS Config agent only if the connector is used | As above; IAP range inbound | **GA** (direct agent); multicloud connector for GCP **public preview** (uses VM Manager / OS Config) | **High** (direct); connector not suitable as the only live path (preview) | Pre-onboarded before session |

Key facts used: device code is the default sign-in on Linux and allows 5 minutes; `--tags` takes `Key=Value,Key2=Value2`; without `--resource-name` an EC2 machine is named by instance ID; the agent must not be installed on Azure VMs; cloned images must connect only after cloning.

**Decision:** direct agent for all three. The multicloud connector is shown on one slide as the at-scale alternative (AWS GA, GCP preview) and is never on the live critical path.
